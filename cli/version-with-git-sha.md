# Embedding Git SHA in CLI Version Output

Show version output like `myapp v0.1.0.0 (a1b2c3d)` where the hash comes from the git commit at build time.

## The Problem

Two build contexts need different strategies:

| Context | `.git/` available? | Strategy |
|---|---|---|
| `cabal build` (local dev) | Yes | Template Haskell via `githash` |
| `nix build` (CI/release) | No (Nix strips it) | CPP flag `-DGIT_HASH` |

## Haskell Side

### Dependencies

In your `.cabal` file:

```cabal
build-depends:
    githash ^>=0.1
```

### Version Module

```haskell
{-# LANGUAGE CPP #-}
{-# LANGUAGE TemplateHaskell #-}

module MyApp.Version
  ( appVersion,
    appVersionWithGit,
    gitCommitShort,
  )
where

import Data.Text (Text, pack)
import Data.Version (showVersion)
import GitHash (GitInfo, giHash, tGitInfoCwdTry)
import Paths_myapp (version)  -- autogenerated by Cabal

-- | Base version from .cabal file
appVersion :: Text
appVersion = pack (showVersion version)

-- | Git info embedded at compile time via Template Haskell.
-- Right if in a git repo, Left with error message otherwise.
gitInfo :: Either String GitInfo
gitInfo = $$tGitInfoCwdTry

-- | Fallback git hash injected via CPP for Nix builds where .git is absent.
nixGitHash :: Maybe Text
#ifdef GIT_HASH
nixGitHash = Just GIT_HASH
#else
nixGitHash = Nothing
#endif

-- | Short git commit hash (first 7 characters).
-- Tries TH first, falls back to CPP-injected hash.
gitCommitShort :: Maybe Text
gitCommitShort = case gitInfo of
  Right gi -> Just $ pack $ take 7 $ giHash gi
  Left _   -> nixGitHash

-- | Full version string, e.g. "myapp v0.1.0.0 (a1b2c3d)"
appVersionWithGit :: Text
appVersionWithGit = "myapp v" <> appVersion <> commitSuffix
  where
    commitSuffix = maybe "" (\c -> " (" <> c <> ")") gitCommitShort
```

**How it works:**

1. `tGitInfoCwdTry` is a Template Haskell splice that reads `.git/` at compile time — works during `cabal build`
2. When `.git/` is missing (Nix builds), TH returns `Left` and we fall back to the CPP `GIT_HASH` macro
3. If neither is available (e.g. building from a tarball), the commit suffix is omitted

### Wiring into optparse-applicative

```haskell
import Options.Applicative

opts :: ParserInfo Command
opts = info (commandParser <**> helper <**> version) fullDesc
  where
    version = infoOption
      (T.unpack appVersionWithGit)
      (long "version" <> help "Show version")
```

## Nix Side

### flake.nix

Capture the git revision from the flake's `self`:

```nix
outputs = { self, nixpkgs, ... }:
  let
    gitRev = self.shortRev or "dirty";

    haskellPackages = pkgs.haskell.packages.ghc9122.override {
      overrides = import ./nix/haskell-overlay.nix {
        inherit pkgs gitRev;
      };
    };
  in { ... };
```

- `self.shortRev` — 7-char git SHA, available when the working tree is clean and committed
- `or "dirty"` — fallback when the tree has uncommitted changes

### haskell-overlay.nix

Pass the SHA as a GHC CPP define:

```nix
{ pkgs, gitRev }:
final: prev: {
  myapp = pkgs.haskell.lib.compose.overrideCabal
    (drv: {
      configureFlags = (drv.configureFlags or [ ]) ++ [
        "--ghc-option=-DGIT_HASH=\"${builtins.substring 0 7 gitRev}\""
      ];
    })
    (final.callCabal2nix "myapp" ../. { });
}
```

**Key details:**

- `builtins.substring 0 7 gitRev` — takes first 7 chars (already short, but consistent)
- The escaped quotes (`\"..\"`) are critical — `GIT_HASH` must expand to a Haskell string literal
- `--ghc-option=-DGIT_HASH=...` is passed at configure time, making the CPP macro available to all modules

## Resolution Order

```
cabal build:  tGitInfoCwdTry reads .git/ → Right GitInfo → use giHash
nix build:    .git/ absent → Left error → fall back to CPP GIT_HASH
tarball:      no .git/, no CPP flag → Nothing → version without commit hash
```
